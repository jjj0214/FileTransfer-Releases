# Public Release Policy

1. **Separation:** Public repository jjj0214/FileTransfer-Releases contains reviewed documentation and installer/source assets only. Never upload private development history, credentials, logs, customer data or signing secrets.
2. **Version:** Stable releases use vX.Y.Z. v1.2.265 and earlier contain the original Slave-only four assets. From v1.2.266 onward, require exactly one version-matched Master Setup and one Slave Setup in a single Release. Do not overwrite tags or assets. Drafts/prereleases are never advertised as latest stable.
3. **Build provenance:** require a clean protected Develop HEAD synchronized with origin, matching Windows FileVersion, verified final sidecar, exact filename and SHA-256.
4. **Code-signing modes:** unsigned releases are allowed only with explicit -AllowUnsigned and -UnsignedDistributionApproved. Windows Authenticode must actually be NotSigned (not invalid/unknown), sidecar required=false and status=NotSigned; no signer may be falsely claimed. Signed releases remain supported separately using an approved signer and -RequireAuthenticode after signing. **SHA-256 does not authenticate a publisher.**
5. **Third parties / GPL:** retain the original unmodified TightVNC 2.8.90 x64 MSI as an independent installation. Bundle the GPLv2 license and current THIRD-PARTY-NOTICES.txt inside the installer. Include the exact corresponding tightvnc-2.8.90-src-gpl.zip next to each distributed installer, with pinned size/SHA-256 and ZIP content validation. Do not substitute a different version or rely solely on an external website link. The source ZIP is TightVNC source, not proprietary PIE source. Review any integration boundary and other third-party obligations. The Open XML SDK 3.3.0 packages (DocumentFormat.OpenXml and DocumentFormat.OpenXml.Framework) are MIT-licensed; the full MIT copyright and permission notice must ship inside the installed Master, Configurator and SlaveMonitor packages at ThirdParty/OpenXMLSDK/LICENSE.txt.
6. **Assets:** historical releases have exactly four Slave-only assets. v1.2.266 onward contains exactly six assets: Master/Slave Setup EXEs and their respective release.json sidecars, matching tightvnc-2.8.90-src-gpl.zip, and SHA256SUMS.txt. Checksums cover all five primary files. Release notes clearly state UNSIGNED or SIGNED.
7. **Publication controls:** create an approved draft and verify exact remote asset names, sizes and GitHub-provided sha256: digests. Publish only with a second approval. Never clobber/delete an existing release asset or publish unexpected content.
8. **Repository protections:** enable GitHub Release immutability where available, protect public main, restrict write privileges and use approved GitHub CLI authentication.
9. **Manual deployment:** Master checks exact allowed download URL, length, GitHub SHA-256, file version, cached SHA and manual consent. It uses the existing authenticated network deployment and target confirmation. No automatic downgrade or Slave-originated GitHub update.
10. **Scope:** v1.2.266+ distributes both installers only in FileTransfer-Releases. Existing Master-only release history must be preserved until deployed legacy Master clients have been manually upgraded to the unified-aware version. The previous repository may not be deleted while clients still depend on it.

The publisher fails closed without validated GPL source, genuine unsigned-or-signed sidecar, explicit unsigned risk acknowledgment when relevant, distribution/legal reviews, approved assets, immutable-release setting review and separately approved publication.
